# 成员个人令牌与智能体共创

日期：2026-10-15。坐标沿用 L2-A2。用户本轮授权：注册登录后可自行创建个人令牌，供自己的智能体共创。

需求理解置信度95%，设计置信度95%。依据现有账号、草稿API、人工审核与成员入群规则；第三方客户端仍未逐项联调。真实多人反馈和云端验收可提高置信度。

## Spec 与体验

- PAT-01：已登录注册账号，无需管理身份、无需先完成入群问答，即可在「智能体共读 → 我的个人令牌」创建、查看和撤销自己的令牌。社群账号页提供入口。
- PAT-02：未登录引导登录；管理会话和Agent Bearer不能代替会员会话。列表只返回自己的名称、前缀、创建/使用/撤销时间，完整令牌只在创建响应中显示一次，不写浏览器持久存储。
- PAT-03：权限仅 content:read / draft:create。读取公开内容无需完成问答；提交草稿与手动投稿一样要求完成问答，固定pending，运营或超级管理员审核发布。心得署名和活动发起人使用令牌所属成员昵称。
- PAT-04：每人最多5枚有效令牌，创建10次/小时。成员的全部令牌共用读取60次/分钟限额，与本人手动投稿共用20次/小时草稿配额；防止轮换令牌放大写入。并发创建由数据库条件INSERT限制，不能只靠先读后写。
- PAT-05：成员不能读取/撤销他人令牌。超级管理员可查看元数据并应急撤销成员令牌；运营角色仍无全局令牌管理权。撤销立即禁止后续请求，已提交草稿保留。
- PAT-06：新增独立 member_agent_keys 表，原 agent_keys、原成员账号、管理密码、D1绑定、域名不改动。历史管理员令牌继续可用；普通成员不能认领它们。

## 接口与传播

- GET /api/account/keys → {keys, maxActive:5, scope}。
- POST /api/account/keys，strict {name}，返回201 {id,name,key,scope}；名称1–60字符，拒绝控制字符；上限429。
- DELETE /api/account/keys/:id：只撤销本人有效令牌；他人/不存在/已撤销均404，不泄露归属。
- 原 /api/agent/content、/api/agent/drafts 兼容两类令牌；原管理员创建接口不变，超级管理员列表/撤销扩大到两类元数据。
- 共享 server/member-agent-keys.mjs 维护本地SQLite与D1的一致权限。消费者：React个人入口、管理后台、MCP/REST指南、PRD与架构。
