# GitHub → Cloudflare 自动部署

2026-10-15。对应私有仓库 `Frog1205/liaoye-reading-club`、现有 Pages 项目 `liaoye-reading`、正式域名 https://liaoye.veynuq.com 。

需求置信度98%，方案置信度95%。当前项目为 Direct Upload，Cloudflare 不支持原地切换原生 Git 集成，因此采用[官方支持的 GitHub Actions + Wrangler](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/)发布到原项目。这样无需更换项目、域名或数据库。

## 触发与执行

推送 `main` 或从 Actions 手动运行 `Deploy liaoye production`：

1. 拉取完整历史，执行源码／秘密排除扫描。
2. 安装 lockfile 中依赖，运行本地与云端处理器契约测试。
3. 使用 Node 24.14 构建前端及 `_worker.js`。
4. 在构建目录写入仅含提交号与构建时间的 `deployment.json`，用于核对线上版本。
5. 校验目标项目、现有域名、原 D1 绑定、原四项管理密码 Secret 和会员密码独立pepper。
6. Wrangler 发布到原项目的 `main` 生产分支。
7. 对比发布前后配置摘要，检查正式域名的新提交、健康接口及公开内容接口。

工作流：`.github/workflows/deploy.yml`。目标与保留检查：`cloud/ci-preservation.mjs`。仅此仓库的 `main` 可部署，其他分支和 PR 不获得生产部署权限。同一时间只运行一个生产流水线，运行中的部署不会被后续推送取消；连续推送时 GitHub 可能用最新一次替换尚未开始的排队任务。

## 密码与数据库保留

- 继续绑定原 `liaoye-reading-db`，不创建、重建或切换数据库。
- 原超级管理员与运营人员的四项 Secret 继续保存在 Cloudflare，不复制到 GitHub，不重算、不覆盖。
- 会员功能单独新增`MEMBER_PASSWORD_PEPPER`，也只在Cloudflare Secret保存；发布前后要求该项存在且配置不变。账号新增表迁移由受控步骤执行一次，CI仍不执行迁移。
- 流程不执行 `cloud/manage.mjs schema/seed/secrets/migrate-roles`，也没有 D1 迁移、SQL执行或数据导入命令。
- 所有集成测试使用临时 SQLite 数据，云端处理器测试也是本地 D1 接口包装，不连接生产数据库。
- 发布保留检查只读 Cloudflare 项目配置与公开 HTTP 接口。它校验绑定与密码配置，不是数据库恢复验证，也不是对所有未来应用代码副作用的证明。
- `wrangler.jsonc` 中如果出现其他 D1 绑定、不同项目或密码 Secret 的源码明文配置，会拒绝部署。确需改动时先单独评估和修改契约。

## CI 授权

Actions 需要两个加密 Secret：

| 名称 | 内容 | 保存位置 |
| --- | --- | --- |
| CLOUDFLARE_ACCOUNT_ID | 当前账号ID | 本私有仓库 Actions Secret |
| CLOUDFLARE_API_TOKEN | 独立的 Pages 编辑令牌 | 本私有仓库 Actions Secret；不进入Git文件 |

令牌名称 `liaoye-github-actions-pages-deploy`，仅当前账号的 Pages Write 权限，不授予 D1、DNS、用户或其他产品管理权限。Cloudflare 当前表单没有 Pages 单项目范围，Pages权限范围为当前账号；工作流的目标固定为 `liaoye-reading`。Pages发布权限仍是可修改应用代码的权限，应限制能向main推送的人。

令牌使用持续有效配置，可在 Cloudflare Account API tokens 随时撤销。撤销或轮换后，更新 GitHub Actions Secret；不要将已有 Wrangler OAuth 登录凭据用作长期 CI Secret，不把网站管理口令放进 Actions。

GitHub工作流令牌仅 `contents: read`；Cloudflare部署Secret只注入配置检查、发布和发布后检查步骤，依赖安装及测试步骤不读取部署Secret。第三方Actions固定为核对过的官方版本commit。

后续数据库结构、认证与域名变更仍是独立任务，不因为自动部署建立就自动获准。实际云资源和Actions账单未作费用承诺，当前不新增付费订阅。
