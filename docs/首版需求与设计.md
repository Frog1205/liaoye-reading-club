# 聊也读书 · 首版需求与设计

> 历史记录：本文描述最初本地首版，保留当时边界。当前已上线并增加双角色管理；现行规格见 [PRD](PRD.md)、[技术架构](技术架构.md) 和 [AI-native 开发拆解](AI-native开发拆解.md)。本文“尚未部署”等语句不代表当前状态。

需求理解置信度：90%。实现方案置信度：92%。

已确认：网站按月／周更新书单和心得；允许接入个人智能体；智能体只能提交草稿，人工确认发布。社群以读书和线下交流为核心，偶尔聊 AI，不争吵，不聊政治、宗教、性。

首版目标是可本地运行、可维护内容、可验证接入的闭环。无需先接入某一家模型供应商，也不把“智能体名称出现在页面上”当成集成完成。

## 内容结构

| 页面 | 成员做什么 | 主理人做什么 |
| --- | --- | --- |
| 共读书架 | 按月／周看书单，推荐书籍 | 发布、编辑、收回书单 |
| 读书手记 | 阅读心得、提交个人心得 | 审阅、编辑、发布 |
| 线下相见 | 提议主题、支持／取消支持 | 审阅提议、登记人数和首场里程碑 |
| 智能体共读 | 查看通用接入指引 | 创建／撤销独立令牌 |
| 关于聊也 | 理解初心、群边界、回答三个问题 | 沿用已确认的社群约定 |
| 社群管理 | 无管理权限 | 口令登录，审阅与维护 |

运营门槛暂按“满 3 人支持”解释为至少 3 人；不包含发起人自动投票。实际群人数人工登记，网站注册不代替微信群人数。达到门槛只表示可筹备，不自动确认活动。

## 技术边界

- React + TypeScript + Vite 渲染界面；单个 Node HTTP 服务提供静态页面与 API；SQLite 持久化。
- 管理会话、成员会话使用 HttpOnly／SameSite Cookie。管理员和智能体权限分离；Agent Bearer 令牌不能作为管理会话使用。
- Agent 令牌仅存 SHA-256 摘要与非完整前缀。入群问答不公开，也不通过 Agent API 提供。
- 内容以纯文本保存和显示，不执行 HTML；输入服务端校验；异站写入和非本机 Host 拒绝。
- 本地 MCP 服务通过带令牌的 HTTP 调用网站；不绕过网站授权直接写数据库。
- 数据流：成员／智能体 → pending → 主理人审阅 → published；可退回 rejected，也可将已发布内容收回 pending。
- 本机管理口令首次随机生成，仅保存在受本机账户保护的文件中。`.env`、运行数据、日志均不属于前端构建和版本管理内容。

## 尚待真实运营信息补齐

1. 首批真实书单、真实心得、群实际人数，以及线下城市、时间和场地。
2. 各个人智能体的准确产品名、版本、可用 MCP／HTTP 配置入口。
3. 公网部署目标、域名、正式登录和成员身份恢复方式。
4. 是否需要多主理人、主题分类、活动日期、报名确认、邮件或群消息通知。

以上事项没有被假装为已接入。新增公网身份和部署属于下一阶段，当前版本明确限制为本机预览。
