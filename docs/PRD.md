# 聊也读书 PRD

版本：1.1 · 快照日期：2026-10-15 · 状态：含已验证上线的会员账号增量，其他后续需求为提案。

需求评估置信度：96%。依据是用户已给出的社群规则、智能体草稿边界、双角色要求，以及代码、测试和线上接口；真实成员需求、持续使用意愿与运营工作量尚未验证。置信度为工程判断，不是统计概率。

会员账号增量已由用户明确授权，登录方式确认采用微信号＋本站密码。需求置信度98%，设计置信度94%。具体ACC-01～06、HN-08及兼容迁移见[会员账号与社群加入](会员账号与社群加入.md)。其他未来提案仍以[决策登记表](ai-native/16-DECISION-REGISTRY.md)为准。

## 1. 产品定义与价值

**一个让读书社群持续更新共读内容，并把线上讨论带到真实相见的网站。** AI 帮成员整理材料，人负责分享内容和社群关系。

“聊也读书”源于聊 AI 久了之后对线下交流的需要。网站服务于社群，而不是用内容生成量替代阅读和见面。重点聊读书，偶尔聊 AI；重点线下互动，欢迎线上畅聊；不欢迎争吵，不聊政治、宗教、性。

| 诊断层 | 当前判断 |
| --- | --- |
| 背景 | 电子阅读多，真实交流少，希望发起线下读书会 |
| 人群 | 主理人、运营人员、读书成员；个人智能体是成员工具，不是社群成员 |
| 场景 | 每月选书、每周慢读、写心得、支持自己想参加的主题 |
| 范围 | 书单 → 阅读 → 心得／提议 → 人工发布 → 支持 → 群内筹备 |
| 数据 | 真实阅读材料、成员自愿问答、运营登记人数；当前线上内容仍为示例 |
| 交付 | 已上线网站、内容管理、通用 REST/MCP 接口；持续运营负责人仍需落实 |
| 价值 | 更容易找到书和同伴，运营者能维持更新节奏；商业价值未验证 |

判断：**继续运营验证，保持当前产品范围**。技术可行性已建立，下一阶段主要验证真实内容供给与成员参与，不能用上线和测试通过证明需求成立。

### 内容规则

- 月度书单周期用 `YYYY-MM`；周度用当周周一 `YYYY-MM-DD`。界面选其他星期会归一到周一，API 直接提交非周一会拒绝。
- 书单的实际存储单位是一条带周期的推荐记录，同一本书可在不同周期出现；没有独立“书籍目录 + 书单集合”模型。
- 心得含标题、书名、署名、正文；正文 20–12000 字符。当前按更新顺序展示，未实现独立的月／周心得归档。用户最初希望按月／周更新心得，**运营上可按节奏发布，产品归档能力仍是缺口**（DEC-02）。
- 活动含主题、描述、意向地点和发起人；没有已确认的日期、人数席位或报名状态。
- 成员提交心得／活动时，服务端强制使用登记昵称署名；智能体署名依赖提交者授权与人工核对，不代表身份已验证。
- 示例必须显式标注，示例活动不可投票。编辑保存会清除示例标记，运营人员应先换成真实材料。
- 内容为纯文本；不提供电子书全文上传、版权资源下载或自动抓取。转载、引用与真实经历由提交者和审核者核对。

### 入群互动

1. 如果推荐一本书，你会推荐什么？
2. 除书籍内容本身，更看重读书会提供哪些附加价值？
3. 是否使用过 AI 辅助阅读？当前选项为经常使用、偶尔试过、还没用过。

网站账号数与实际读书群人数分开。微信号忽略大小写后唯一、昵称允许重名；未核验微信归属，仍不能证明一个自然人只登记一次。旧浏览器身份需注册升级，持有旧Cookie时保留原member_id和投票。

### 活动门槛

```text
canPlan = 非示例 && 支持数 >= 3 && (首场已经完成 || 实际群人数 >= 100)
```

实际群人数由管理人员人工登记；未登记时不满足首场人数条件。发起人不会自动获得一票。原始“满 3 人以上”沿用当前“至少 3 人”的实现，语义需改动时先更新规则与测试。达到门槛只提示可以筹备，日期、场地、最终参加人仍在群内确认，不自动成行。

### 内容状态

| 触发者／动作 | 原状态 | 结果 | 说明 |
| --- | --- | --- | --- |
| 成员／Agent 投稿 | 无 | pending | 不公开，不可指定发布状态 |
| 管理创建 | 无 | published | 当前创建即发布，没有“管理另存草稿” |
| 管理编辑保存／审核发布 | pending、rejected、published | published | 保存即发布；内容类型不可改变 |
| 管理退回 | pending | rejected | 非待审内容退回返回 409 |
| 管理收回 | 任一已有状态 | pending | 现有 API 未限制必须从 published 发起 |

界面“退回”对应 `rejected`，当前没有退回原因、成员通知或成员自行修改重提入口。没有历史版本恢复或硬删除接口。

## 4. 核心用户旅程与体验契约

| EX ID | 最短成功路径 | 必须看得懂的状态 | 失败与恢复 |
| --- | --- | --- | --- |
| EX-01 | 打开书架 → 选月／周和周期 → 查看书 → 读详情 | 当前周期、示例、无内容 | 无效周期／方向回退到有效值；无结果可清空搜索 |
| EX-02 | 加入共读 → 三问与同意 → 投稿 → 等待审核 | 昵称、投稿成功但未公开 | 校验失败保留表单输入供修改；不承诺跨会话草稿恢复 |
| EX-03 | 管理登录 → 待审列表 → 核对 → 编辑保存发布 → 公共页查看 | 角色、待审、已发布、已退回 | 失败显示错误；误发布可收回，已被人读过无法撤回影响 |
| EX-04 | 看真实提议 → 支持 → 看到票数与筹备提示 | 已支持、取消支持、首场门槛 | 示例禁投；未登记先完成登记；重复支持只计一票 |
| EX-05 | 超级管理员发令牌 → 本地客户端配置 → 整理材料 → 提交草稿 | API 成功且 reviewRequired，不是已发布 | 15 秒请求超时后先查草稿箱，不能盲目重试 |

主表面是书架、阅读页和提议卡片；沿用已有米白、橄榄绿、陶土色和编辑式排版，以文字与真实交流为中心。视觉事实来自当前 `src/styles.css` 和历史截图；不引入新的外部参考设计。书封为示意绘图，不是原书封面。导航用 Hash 路由，移动端为抽屉，表单与详情采用弹窗。

无 UI 新设计，本次保留基线。视觉意图判断置信度 95%，当前视觉复核置信度 80%（本轮未重新逐屏检查）；历史浏览器记录不能替代真实成员对易用性的评价。键盘、焦点、200% 缩放、读屏与实体手机完整检查见 EV-07，尚未全部完成。

## 5. 智能体产品契约

定位为 **Draft（准备草稿）**，与开发过程建议采用的 A2 自主度分开。

| 项目 | 当前约定 |
| --- | --- |
| 触发 | 用户在自己的智能体客户端发起整理任务；本站没有定时任务 |
| 输入 | 用户有权使用的笔记、书目信息和公开站点内容 |
| 可用工具 | 读公开内容；提交书单、心得、活动草稿 |
| 状态 | 外部整理过程不可见；本站仅能证明请求成功／失败和持久化的 pending 状态 |
| 审批 | 运营人员或超级管理员核对后发布 |
| 重试 | MCP 每次 HTTP 请求超时 15 秒；草稿创建没有幂等键，重试可重复 |
| 暂停／取消／撤销 | 本站无模型任务暂停／取消；撤销令牌阻止后续调用，不删除已有草稿 |
| 隐私 | 不向 Agent 提供入群问答、其他草稿、会话或后台令牌列表 |
| 模型 | 用户自选；本站不托管模型、不收供应商 API Key、不支付模型调用费用 |

WorkBuddy、Codex、Claude Code、OpenClaw、DSH、ZCode、Kimi Code、DuMate 是接入目标；当前只验证通用 SDK 协议链路，不宣称所有产品已接入。禁区和不编造经历／引文是提示与人工审核要求，确定性权限由服务端实施；本站未实现自动语义审核。

## 8. 下一阶段：一次只验证一个瓶颈

建议先做 **两周真实内容运营试点**，再决定是否增加功能。试点目标是验证“成员材料 → 整理草稿 → 人工核对 → 发布”的成本和完成率，不能要求成员让渡后台权限。

建议试点样本：1 名运营者、3–5 名自愿成员、至少 1 份真实月书单、2 份周阅读安排、3 篇心得。以上是待确认的实验设计，不是现有用户数据或承诺产出。运营者可按已有权限开展日常更新，组织试点与招募仍需落实责任人。

| 结果指标 | 计算口径 | 当前基线 | 决策用途 |
| --- | --- | --- | --- |
| 内容闭环完成率 | 发布的真实任务数 / 发起的真实任务数，记录放弃与失败 | 未测 | 是否解决持续更新问题 |
| 发布交付时间 | 材料收到至公开可见，记录中位数和样本数 | 未测 | 主瓶颈在材料、AI 还是审核 |
| 人工分钟／成功任务 | 所有尝试中的整理、核对、协调、返工时间 / 成功数 | 未测 | 是否减少主理人负担 |
| 一次通过率／返工率 | 首次审阅通过数 / 提交数；区分缺材料、事实错、表达与工具失败 | 未测 | 下一轮只改最主要原因 |
| 总尝试成本／成功任务 | 模型、工具、基础设施分摊及人工时间分别记账 | 未测 | 零成功时该比值未定义 |
| 越权公开与错误发布 | 按真实事故计数，并记影响与恢复 | 未建立台账 | 出现越权立即停受影响链路 |
| 活动转化 | 真实提议数、达门槛数、实际完成场次，分别计数 | 未测 | 网站是否带来真实见面 |

本期暂不增加：自动发布／自动群消息、多模型编排、内置聊天机器人、支付、活动报名、微信官方授权登录、阅读打卡、评论点赞和复杂推荐。这些不是永久拒绝，须以试点证据进入新 Spec。
