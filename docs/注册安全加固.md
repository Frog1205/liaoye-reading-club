# 注册安全加固 · Spec / Plan

2026-10-15，用户要求核查并防范注册攻击、恶意写入。沿用L2-A2与原部署授权；需求理解置信度98%，设计置信度92%。保留现有账号、两套后台密码和数据库；不改变DNS托管、不新增付费服务、不进行生产压力攻击测试。

## 现状和缺口

已具备参数化SQL、严格Schema、字段长度／请求体限制、微信号唯一约束、原子注册、密码派生摘要、服务端会话、同源写入、私有联系人鉴权、投稿人工审核。原注册限流10次/小时/IP、登录30次/15分钟/IP及10次/15分钟/微信号。

主要缺口是没有真人验证，轮换IP仍可批量注册；限流行清理依赖管理员登录；问答并发提交需防止第二次覆盖。自填微信号仍不能证明归属；验证码也不能证明真人唯一。

## 本次契约与验收

| ID | Guard及确定性验收 |
| --- | --- |
| SEC-01 | 生产注册强制Cloudflare Turnstile，后端Siteverify验证success、请求hostname及action=register。缺失、伪造、过期／重复、错误域名／用途一律拒绝；服务不可用或配置不全时禁止注册，已有登录继续有效 |
| SEC-02 | 原每IP10次/小时之外，增加5次/分钟；不信任客户端X-Forwarded-For，云端取Cloudflare覆盖的连接IP，本地取socket。超限429；限流计数写入饱和，过期记录限量清理 |
| SEC-03 | 注册／登录请求体最大8KiB；严格拒绝额外权限字段、控制字符昵称及空白密码。所有数据库写入继续绑定参数；SQL／HTML不得变成可执行指令 |
| SEC-04 | 两种管理角色可临时关闭／恢复新注册，变更服务端生效、记审计；匿名不能操作，停注册不影响已有登录和公开阅读 |
| SEC-05 | 入群问答通过事务条件更新，只允许首次提交，竞态重复不得覆盖第一次结果 |
| SEC-06 | Turnstile Secret只保存在Cloudflare及被Git忽略的私有配置；Sitekey可公开。CI检查生产配置及原管理密码／D1绑定保留，不采用官方测试密钥上线 |

模块MOD-02／03／05。新增GET /api/account/security返回注册开关、是否要求验证及公开Sitekey；注册body新增可选turnstileToken，生产由后端强制检查；GET/PUT /api/admin/registration维护开关。UI仅注册页加载官方验证组件并提供失败重试，登录不增加验证步骤。CSP仅追加challenges.cloudflare.com脚本／frame来源。无旧表重建或个人数据迁移。

## 验证边界与发布

临时库验证SQL注入、跨站、越权、异常大小／字段／控制字符、并发重复、验证码失败／超时／重放、IP限流伪造、注册开关与限流清理；官方测试密钥仅用于本地组件验证。正式域名仅做少量拒绝路径检查并核对数据摘要，不暴力压测或制造批量垃圾账号。

Cloudflare widget只限本站生产域名和Pages主域名，Managed模式、不启用付费选项或WAF预放行；配置Secret后经原GitHub Actions发布。出现配置缺失或widget失败时展示重试，不静默放行。回退只选择保留验证及开关的版本；未加固的旧代码不会遵守新注册开关，不能仅改setting就安全回退，需要先在外层阻断注册路由并验证。

参考：[服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[CSP](https://developers.cloudflare.com/turnstile/reference/content-security-policy/)、[官方测试方式](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)。完整WAF策略、DDoS能力和费用告警需单独核对，不能把Pages HTTPS或本次测试等同于全面安全审计。
