# 两种管理后台

两种角色共用“社群管理”登录入口，服务端根据口令决定角色。登录后进入不同的后台界面：超级管理员后台或社群运营工作台。

| 能力 | 超级管理员 | 社群运营人员 |
| --- | --- | --- |
| 发布和编辑月／周书单 | 可以 | 可以 |
| 发布和编辑心得、活动提议 | 可以 | 可以 |
| 审阅、发布、退回和收回内容 | 可以 | 可以 |
| 登记群人数和首次线下活动里程碑 | 可以 | 可以 |
| 维护群主／运营入群联系人 | 可以 | 可以 |
| 查看、创建、撤销智能体令牌 | 可以 | 不可以 |

原管理口令对应超级管理员，新运营口令保存在本机受版本管理忽略的 `data/operator-access.json`，口令实际值不写入前端或本文档。Cloudflare 仅保存两种口令各自的派生摘要和随机盐。

权限由服务端会话中的 `role` 决定。客户端提交角色名不能取得权限，运营人员直接请求令牌接口会收到 403，运营后台的响应也不包含令牌列表。切换口令重新登录时，原管理会话会失效。

云端采用新增 `management_sessions` 表的方式迁移角色；旧版本数据库表保留，迁移只在首次创建角色会话表时导入原有超级管理员会话。更新不会重新导入已失效的旧会话。

会员已提供微信号＋密码的独立账号，但不授予后台权限。运营人员仍共用运营口令，不具备个人管理审计。两种管理角色均可维护联系人；只持管理身份不能读取会员专用社群接口，需要另行注册会员。

验证记录：本地和云端处理器各 17 项测试，含运营人员正常操作、令牌接口拒绝、角色字段注入拒绝、切换会话失效。正式域名验证结果保存在 `artifacts/role-verification.json`。
