## 4. 后续发布的最小门禁

1. 受影响 FR/AC、契约、模块 Owner 和授权明确；体验主路径和红黄变更已处理。
2. 双处理器核心测试与前端／Worker构建通过；新增能力有独立反例，不能只照抄实现来测。
3. 迁移前有准确目标、影响范围、备份／恢复和兼容步骤，恢复未测不得宣称可恢复。
4. 重大权限／数据改动有独立 Reviewer 证据；独立审阅未完成时明确保留 NOT-TESTED。
5. 在已有或适用新增授权内发布后，核验正式域名、HTTPS、权限和核心写入；记录实际数据副作用和清理／保留方式。
6. 必需检查 FAIL 或 NOT-TESTED 时，不能标整体PASS；停止受影响发布并记录恢复／修复动作。

首版文档任务没有发布代码；后续按用户授权建立并验证了CI部署。当前CI强制执行历史扫描、双处理器测试、构建、目标预检及上线保留核验，独立审阅、迁移审批和恢复演练未自动化。本次CI不修改管理口令、生产业务数据或DNS；新建部署令牌仅保存在Actions Secret中。
